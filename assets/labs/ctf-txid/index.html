Name that transaction

Explorers, wallets and court exhibits all refer to a Bitcoin transaction by its ID, the txid. No registry hands txids out. Anyone holding a transaction's raw bytes can compute it, and so can you.

    Flag 1: the txid

    Debrief

    Why it matters

    The txid is a fingerprint of the transaction's exact bytes. Change a single byte (a different amount, a different recipient) and you have a different transaction with a different ID. That's why a txid in a report pins down exactly one transaction, and why nobody can quietly edit one afterwards.

    Why backwards?

    Bitcoin's code treats a 32-byte hash as one large number and stores it least-significant byte first. Explorers print that number most-significant byte first. It's the same 32 bytes in the opposite order. If an ID you were given "doesn't exist", check its byte order before anything else.

    Say it to a general

    One sentenceNobody assigns a transaction ID. It's computed from the transaction itself, so every computer on the network agrees on it, and any change to the transaction changes the ID.

    Go deeper: Flag 2, the segwit txid

    Since 2017 most transactions use segregated witness (segwit): the signatures move into a separate witness section. Here is a segwit transaction. If you hash all of it, you get its wtxid. The txid that explorers, wallets and other transactions use leaves some bytes out. Work out which ones, remove them in the workbench, and compute the txid.

    Hint 1BIP 141: the txid is computed over the transaction in the original, pre-segwit format.
    Hint 2Remove the two bytes straight after the version (marker 00, flag 01) and the whole witness section that sits just before the last 4 bytes (the locktime).

    Why leave the witness out?

    Before segwit, anyone relaying a transaction could re-encode its signature without invalidating it. The payment still went to the same place, but its txid changed. Software tracking the payment by txid could lose it, and transactions built on top of an unconfirmed one broke. This was called transaction malleability. Taking the witness out of the txid fixed it, and that fix is what made payment channels such as the Lightning Network practical.
